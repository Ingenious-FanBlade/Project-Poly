## 1. 职责

- 管理卡牌目标的暂选、改选、取消与最终确认输入，并在最终确认前于打出中的卡面展示数值预演。候选目标、预演和正式结算分别由战斗规则系统提供；UI 只显示结果并转交输入。
- 读取实体已提交的永久状态实例及其重复模式，展示能力图标与对应数值。
- 提供主动结束我方回合的输入入口，将请求交给回合流程处理，读取当前阶段与待处理请求状态反馈操作结果。
- 提供复活冷却已结束角色的手动部署入口：玩家选定角色与目标格后一次提交部署命令，合法性由规则层按最新状态验证。读取我方角色的上场状态与剩余冷却并加以展示。

## 2. 设计约束

- 所有可取消的 `choose()` 先完成暂选，再进入最终确认阶段；选择目标不等于确认出牌。最终确认前允许改选与取消，不产生实际扣费、卡牌移动或真实 `PlayId`，不消耗真实战斗随机数，也不向真实战斗发布规则消息；预演副本内仍模拟对应消息。
- 卡面只更新卡牌定义显式绑定的可变数值槽。确定性预演值取效果执行前修正后的请求值，不把护盾等规则造成的实际生命损失误写为伤害数值；随机、隐藏或依赖未知后续结果的槽显示不确定标记。
- 永久能力的展示由 `StatusDefinition.repeatMode` 决定：可重复可叠加时显示一个能力图标及叠加后的数据字段值；可重复不可叠加时按独立状态实例重复显示对应能力图标，不将各实例的数值字段相加；不可重复不可叠加时只显示一个图标，不显示统一为 `0` 的数值字段。UI 从已提交状态读取实例与数值，合并、去重等规则由实体与状态系统执行。
- 预演需覆盖出牌提交消息与连锁，以及卡牌脚本中的直接效果；使用与正式结算相同的规则顺序，但隔离预演数据，不改变实际 `BattleState`。目标或战斗状态变化时作废旧预演，规则系统重建待提交执行帧并验证暂选；先前选择影响了后续候选时，受影响的后续暂选也须重选。最终确认仍依最新状态复验，不直接应用预演结果。
- 出牌提交后，卡牌程序可能再发起不可取消的选择。UI 在已产生的表现事件播完后展示候选，不提供取消入口，也不进行预演或最终确认；玩家确认的选择立即交给规则系统，不能改选。候选为空时，规则系统直接返回空结果，不请求 UI。预演到达这类选择即停止，其后数值槽显示不确定。
- 玩家在目标暂选／最终确认阶段请求结束回合时，回合流程先取消未提交尝试，UI 清理暂选、高亮与预演展示。卡牌已经提交且程序／连锁仍在结算时，回合流程保留结束请求并等待稳定后处理；已登记的结束请求不可撤回。UI 不直接切换阵营、撤回消费或中断结算。结束规则与准入以[战斗流程与回合状态机](战斗系统/战斗流程与回合状态机.md)为准。
- 规则层推进不等待表现。已产生的表现事件播放完之前，UI 不发送出牌、部署或结束回合命令；战斗结束后由 `GameFlow` 在表现播完后切换界面。这只决定输入与切换时机，不改变规则结果。

## 3. 核心概念

- **目标暂选**：当前 `choose()` 的候选目标与玩家选择仅用于待确认的出牌尝试；改选会使原预演失效。
- **卡面数值槽**：卡牌定义显式绑定、允许预演替换的数值展示位置；每槽显示确定的修正后请求值，或不确定标记。
- **最终确认**：所有可取消选择完成后提交一次确认输入，战斗规则系统据最新状态重新验证，再进入正式出牌事务。

## 4. 数据模型

- UI 持有待确认尝试的目标暂选与预演展示结果；预演结果按卡牌定义的数值槽标识关联显示值或不确定标记，不把预测结果写回卡牌定义或实际战斗状态。
- 永久能力图标关联所属 `EntityId`、状态定义 ID 与状态实例 ID。可重复不可叠加的同一能力可对应多个图标；可重复可叠加及不可重复不可叠加的能力各对应一个图标，按重复模式决定是否显示数据字段值。

## 5. 运行流程

1. 基本出牌条件通过后，调度器在 `choose()` 处暂停，UI 收集并保存暂选目标；玩家可在允许阶段取消尝试。
2. 所有可取消选择完成后，向规则系统请求预演；UI 在打出中的卡面填充可变数值槽，展示最终确认、改选和取消操作。
3. 改选目标或战斗状态变化时撤销旧展示并重新请求预演。取消时结束尝试且不产生实际状态变化。
4. 玩家最终确认时提交所选目标；规则系统重新验证并正式执行。验证失败时不展示旧预演为最终数值，本次尝试不发生消费。
